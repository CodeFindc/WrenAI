# Wren Sample Project

A minimal, zero-dependency Wren MDL project used by the demos in this
directory (`langchain_demo.py`, `langgraph_demo.py`) and by the dual-track
servers (`PROJECT_PATH=./wren_project`).

## Why it runs without a database

Both models (`orders`, `customers`) use `ref_sql` with inline `SELECT ...
UNION ALL` data. The `duckdb` data source opens an in-memory DuckDB session
and evaluates those `ref_sql` subqueries directly — no `.duckdb` file, no
CSV, no external server. Swap the profile in `~/.wren/profiles.yml` to point
at a real database and replace `ref_sql` with `table_reference` when you are
ready to model your own warehouse.

## Build & index

Register the bundled profile once (writes `~/.wren/profiles.yml`):

```bash
cd wren_project
wren profile add sample-duckdb --from-file sample_profile.yml --activate
wren context set-profile sample-duckdb   # binds profile + data_source into wren_project.yml
wren context validate                     # check YAML structure (no DB needed)
wren context build                        # compile YAML → target/mdl.json
wren memory index                         # optional: build the .wren/memory/ index
```

`wren context build` is the only required step before running the demos —
they read `target/mdl.json`.

> **Container flow differs.** `entrypoint.sh` / `start_server.bat` /
> `generate_profile.py` rebuild the profile from `DATASOURCE` / `DB_*` env
> vars on every start and rebind `wren_project.yml`, so the hardcoded
> `profile: sample-duckdb` above is replaced. Set `DATASOURCE=duckdb` and
> leave `DB_PROFILE_TIMEOUTS=0` (duckdb is not mysql/doris) in `.env`.

## Try a first query

```bash
wren --sql "SELECT customer, sum(orders.total) FROM orders GROUP BY customer"
```

Or via the demos:

```bash
export OPENAI_API_KEY=sk-...
export PROJECT_PATH=./wren_project
python examples/langchain_demo.py
```

## Layout

```
wren_project/
├── wren_project.yml      # project manifest (data_source: duckdb)
├── models/
│   ├── orders/metadata.yml       # ref_sql inline data + calculated column
│   └── customers/metadata.yml   # ref_sql inline data
├── relationships.yml    # orders → customers (MANY_TO_ONE)
├── instructions.md      # business rules for the agent
└── target/              # generated by `wren context build` (gitignored)
```

## What it demonstrates

- A `table_reference`-free model (`ref_sql`) so the sample is self-contained.
- A calculated column (`orders.total_with_tax = total * 1.1`).
- A relationship column (`orders.customer`) so `orders.customer.first_name`
  resolves through an auto-join.
- `properties.description` on columns — these feed the memory index that
  agents retrieve context from.
